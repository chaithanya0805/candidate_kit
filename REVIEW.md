# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Grace period logic floors before comparison (`minutes if minutes > 10 else 0`). A punch at 09:40:01 (601s) computes `minutes = 10` and returns 0 instead of 10. Also disregards timezones and overnight shifts. | Input: shift 09:30, punch-in at 09:40:01 IST. Rule R2 requires 10 late minutes; starter returned 0. | Calculated total elapsed seconds in IST from shift start; if `diff_seconds > 600`, returned `int(diff_seconds // 60)`, else 0. |
| 2 | `compute_work_hours` (lines 40-41) | Uses Python built-in `round(..., 2)` which performs banker's rounding (round half to even) instead of round-half-up required by R4. | Input: 32670 seconds (9.075 hours). Built-in `round(9.075, 2)` gives 9.07 instead of 9.08. | Used `Decimal.quantize(Decimal("0.01"), rounding=ROUND_HALF_UP)`. |
| 3 | `compute_overtime` (lines 44-47) | Missing 30-minute threshold check (R3); returns overtime for any duration > 0. For overnight shifts, builds end time on the start date rather than the next calendar day. Comparing naive with aware datetime causes `TypeError`. | Input: shift end 18:30, punch-out at 18:35 IST. Starter returned 5 min overtime; sample 1 and R3 require 0 min. | Added threshold check `diff_seconds >= 1800`; rolled overnight shift end to next calendar day; enforced IST awareness. |
| 4 | `health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking if MongoDB is responsive. | Stop MongoDB and call `GET /health`. Starter returned 200 OK instead of required 503. | Added `client.admin.command("ping")`; on failure, raise `HTTPException(503)`. |
| 5 | `create_employee` (lines 78-85) | Concurrency race condition: checks `find_one` before `insert_one` without a database unique index. Concurrent requests with same `emp_code` both succeed. | Run concurrent POST `/employees` with identical `emp_code`. | Created unique index on `emp_code` at startup; caught `DuplicateKeyError` and returned 409. |
| 6 | `create_employee` (lines 78-85) | Missing schema validations: no regex pattern on `emp_code`, email, or shift times; no validation that `shift_start != shift_end`. | POST `/employees` with `shift_start: "09:30"` and `shift_end: "09:30"`. Returned 201 instead of 422. | Added strict Pydantic model with regex patterns, lengths, and validator enforcing `shift_start != shift_end`. |
| 7 | `create_employee` (lines 81-85) | `created_at` stored local naive datetime and returned datetime object instead of integer epoch milliseconds (`EpochMillis`). | Inspect response body: `created_at` was ISO string or datetime object, violating OpenAPI contract. | Set `created_at` as UTC datetime in Mongo and serialized to integer epoch milliseconds in response. |
| 8 | `list_employees` (line 93) | Off-by-one pagination error: `skip = page * page_size`. For `page=1`, skips 20 employees. | `GET /employees?page=1` returned records 21..40 instead of 1..20. | Changed to `skip = (page - 1) * page_size`. |
| 9 | `list_employees` (line 94) | `total = db.employees.count_documents({})` ignored the `department` filter query `q`. | `GET /employees?department=Sales` returned total company count instead of Sales count. | Changed to `db.employees.count_documents(q)`. |
| 10 | `list_employees` (line 95) | Missing sort order: results returned in natural database order instead of `emp_code` ascending. | Contract requires sorted by `emp_code` ascending; unordered documents returned. | Added `.sort("emp_code", ASCENDING)`. |
| 11 | `punch_in` (line 101) | Unhandled unknown employee: `emp = db.employees.find_one(...)`. If None, `emp["shift_start"]` raises `TypeError`, causing 500 error instead of 404. | POST `/attendance/punch-in` with `emp_code: "EMP9999"`. Returned 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |
| 12 | `punch_in` (line 104) | Concurrency race condition: check-then-insert allows duplicate punches for the same employee and date. | Parallel POST `/attendance/punch-in` for same employee and date. | Created compound unique index on `("emp_code", 1), ("date", 1)`; caught `DuplicateKeyError` and returned 409. |
| 13 | `punch_in` (lines 102-103) | Disregards IST timezone and overnight shift date mapping: `ts = datetime.fromtimestamp(...)` and `ts.date().isoformat()` assigns wrong date for overnight shifts. | Punch-in at 01:00 IST for 22:00-06:00 overnight shift incorrectly assigned to current date instead of previous day. | Implemented `get_attendance_date` applying IST timezone and overnight shift date rollover per R1. |
| 14 | `punch_in` (lines 119-120) | Injected unauthorized `id` field (`doc["id"] = str(res.inserted_id)`) and returned datetime objects instead of epoch milliseconds. | Contract schema for `AttendanceRecord` has no `id`/`_id` field and requires epoch milliseconds for punch times. | Removed `_id`/`id` and serialized instants to epoch milliseconds via `serialize_attendance_doc`. |
| 15 | `list_attendance` (lines 144-150) | In-memory loading and sorting: `docs = list(db.attendance_logs.find(q))` loads entire collection into memory and sorts in Python; unscalable at ~100k docs. | High latency and memory exhaustion on large collections. | Replaced with database-level query: `.sort([("date", DESCENDING), ("emp_code", ASCENDING)]).skip(skip).limit(page_size)`. |
| 16 | `list_attendance` (line 125-144) | Missing date range validation (`date_from > date_to` must return 422) and missing secondary sort on `emp_code` ascending. | `GET /attendance?date_from=2026-07-10&date_to=2026-07-01` returned 200 instead of 422. | Added `if date_from > date_to: raise HTTPException(422)` and secondary sort on `emp_code`. |
| 17 | Database startup (global) | No database indexes created at application startup. | Missing uniqueness guarantees and queries result in COLLSCAN. | Added `init_indexes()` in lifespan context manager creating all required indexes idempotently. |

Also note anything you looked at and decided was **not** a defect, and why:
- `IST = timezone(timedelta(hours=5, minutes=30))` at line 25: Fixed offset timezone is correct and necessary for Indian Standard Time as India does not observe Daylight Saving Time.
- `load_dotenv()` at module top-level: Acceptable and convenient for local development, provided environment variables from the OS take precedence over `.env` values (`override=False`).
